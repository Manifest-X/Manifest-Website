    Why Manifest

    HTML, restored as a first-class development surface.

    For a decade, the web platform has been buried under build pipelines. Every new project starts with thousands of dependencies, a bundler config you have to learn, and a months-long ramp before you ship a single line of HTML.

    Manifest is the framework for people who'd rather just write HTML. Routing, reactivity, components, data binding, localization, prerendering, AI-editor integration — all built in, all available the moment your browser parses a single <script> tag.

    No node_modules. No vite.config.js. No "why isn't hydration working" tickets.

    A counter, two ways
    React (with build step) 
    import { useState } from 'react'

                export default function Counter() {
                const [n, setN] = useState(0)
                return (
                <button onClick={() => setN(n + 1)}>
                Clicked {n} times
                </button>
                )
                }
    Manifest (no build) 
    <button x-data="{ n: 0 }" @click="n++">
                Clicked <span x-text="n">0</span> times
                </button>
    Capabilities

    Everything a website needs. Nothing it doesn't.

    Manifest ships as a single script tag and unlocks the patterns you'd otherwise reach for a full framework to get. Each capability has thoughtful defaults and gets out of your way.

    Components without imports

    Drop in <x-header> and Manifest resolves it from your project's components/ folder. No bundler config, no import statements, no JSX.

    Reactive data with $x

    Register YAML, JSON, CSV, or HTTP sources in manifest.json. Access them anywhere with $x.sourceName. Search, query, and routing magic methods come free.

    Static rendering for SEO + AEO

    Run npx mnfst-render to compile every route to a crawlable HTML file with auto-generated meta tags, OG image snapshots, JSON-LD, and llms.txt for AI crawlers.

    Localization, built in

    CSV locale columns or per-language YAML files. Manifest routes locale-prefixed URLs, sets lang and dir, and prerenders one HTML per locale with proper hreflang.

    Markdown to HTML

    Drop .md files anywhere and render with <x-markdown>. Syntax-highlighted code, frontmatter, automatic heading anchors — no plugins to configure.

    Themeable, Tailwind-compatible

    Manifest's CSS custom-property theme works on its own, or drop in Tailwind for utility-first styling. Both coexist; prerender compiles Tailwind to static CSS automatically.
    Comparisons

    How Manifest compares.

    Manifest sits at an unusual point in the framework landscape — HTML-first like HTMX, reactive like Vue, prerendered like Astro, all with no build step. Here's how it stacks up against each:

    React powers complex single-page applications with a vast component ecosystem. Manifest takes a different path: HTML stays the source of truth, with reactivity layered in via Alpine.

    Aspect React Manifest
    Build step required Yes (Vite, Next.js, etc.) No
    Runtime size ~40 KB+ (React + ReactDOM) ~30 KB (Alpine + Manifest core)
    Component model JSX + JavaScript classes/functions HTML files in a folder
    State management Hooks, Context, Redux, Zustand… $x magic method + Alpine x-data
    Static rendering Next.js / Remix required Built-in via npx mnfst-render
    Learning curve Steep (JSX, hooks, rules of hooks) Shallow (HTML + Alpine directives)

    Pick React for large SPAs with a dedicated frontend team. Pick Manifest when you want production sites and apps without committing to a build pipeline.

    Vue and Manifest share an HTML-first philosophy. Vue's .vue single-file components require a build step; Manifest's HTML components don't.

    Aspect Vue Manifest
    Build step required Yes (Vite) No
    Component format .vue single-file (template + script + style) .html file
    Reactivity ref(), reactive(), computed() $x magic + Alpine x-data
    Routing vue-router (separate dependency) x-route attribute (built in)
    Static rendering Nuxt.js / VitePress Built-in via npx mnfst-render
    Ecosystem size Very large Growing; compatible with Alpine plugins

    Vue is excellent if you're already invested in its tooling. Manifest is the right pick when you want Vue-style reactivity without the .vue file format and build step.

    HTMX leans on the server to render HTML fragments over the wire. Manifest is fully client-side reactive with built-in data sources — pick based on where your data lives.

    Aspect HTMX Manifest
    Primary model Server-rendered HTML fragments Client-side reactive HTML
    Backend coupling Tight (server emits HTML) Loose (any data source)
    Components No (uses partials) Yes (<x-name> resolved from files)
    Local data sources Server-side only YAML, JSON, CSV, API, Appwrite
    AI editor integration None Manifest AI (MCP server)
    Static rendering Not the focus Built-in

    Use HTMX when your backend renders the HTML. Use Manifest when you want a client-driven site with optional cloud data.

    Astro and Manifest both prerender. Astro's strength is its multi-framework component story; Manifest's is shipping with no build step.

    Aspect Astro Manifest
    Build step required Yes (Node + Astro CLI) No
    Component model .astro files + React/Vue/Svelte islands .html files + Alpine reactivity
    Static output Yes (HTML + hydrated islands) Yes (static MPA + client hydration)
    Runtime requirement Node.js during dev/build Browser only
    Hosting Static host (after build) Static host (no build needed)
    Image optimization Built-in Manual + auto OG snapshots

    Pick Astro for component-island flexibility across frameworks. Pick Manifest when one consistent HTML-first approach is enough and you want zero build time.

    Manifest is built on Alpine — it's not a replacement, it's a superset. Alpine gives you reactivity in HTML; Manifest adds the rest of a framework around it.

    Aspect Alpine.js Manifest
    Reactivity (x-data, x-text, etc.) Yes Yes (uses Alpine directly)
    Components Manual Built in (<x-name>)
    Routing Plugin Built in (x-route)
    Data sources Manual fetch Built in ($x.* from yaml/json/csv/api)
    Static rendering Not provided Built in (npx mnfst-render)
    AI editor integration None Manifest AI

    Use Alpine alone for sprinkles of reactivity on existing pages. Use Manifest when you want components, routing, data, and prerendering on top of Alpine's foundation.

    Production

    Built for production from day one.

    Manifest is what's running this site. Every capability below is in active use, not a roadmap promise. The framework was hardened on real-world traffic, not benchmark demos.

    SEO-optimized prerender Per-page meta, OpenGraph, Twitter Cards, and JSON-LD structured data. Auto-snapshot OG images at 1200×630. Smart defaults extract titles and descriptions from page content — no config required.
    AI crawler ready (AEO) Generated llms.txt and llms-full.txt let GPTBot, ClaudeBot, PerplexityBot, and other AI crawlers find and summarize your content in plaintext.
    Multi-locale routing Generate locale-prefixed routes with proper hreflang alternates, lang/dir attributes, and translated content from a single source.
    Static-MPA performance Every route deploys as static HTML — no SPA hydration overhead, no JavaScript blocking first paint. Core Web Vitals stay green by default.
    Appwrite-powered backend Optional first-class integration for authentication, databases, storage, and realtime — without writing backend code.
    Snapshot caching Content-hash cache skips re-snapshotting unchanged routes on rebuild — meaningful at sites with hundreds of pages across multiple locales.
    Get started

    From zero to running in one HTML file.

    Open a text editor. Paste the snippet below into index.html. Open it in a browser. That's the entire setup.

    <!DOCTYPE html>
            <html lang="en">
            <head>
            <title>My Manifest site</title>
            <link rel="manifest" href="/manifest.json">
            <script src="https://cdn.jsdelivr.net/npm/mnfst@latest/lib/manifest.min.js"></script>
            </head>
            <body>
            <h1>Hello, Manifest</h1>
            <button x-data="{ n: 0 }" @click="n++" x-text="n">0</button>
            </body>
            </html>

    FAQ

    Frequently asked questions.

    For developers, for non-developers, and for everyone in between. If your question isn't here, the docs or the GitHub discussions probably have it.

    What is Manifest?

    Manifest is a framework that extends HTML for building production websites and web applications. It bakes routing, components, reactive data, localization, markdown, and static prerendering directly into HTML — no build pipeline, no bundlers, no framework lock-in. Drop in a single <script> tag and start building.

    Who is Manifest for?

    Developers who want to ship the web platform, not abstract over it. Manifest is equally suited to marketing sites, documentation, dashboards, blogs, internal tools, and full applications. With Manifest AI, it also works well for non-developers who build with AI coding assistants.

    Do I need to know React, Vue, or another framework first?

    No. Manifest is HTML-first. If you can write HTML, you can build with Manifest. Familiarity with Alpine.js helps, since Manifest is built on it — but it isn't required to get started.

    Is Manifest free?

    Yes. Manifest is open source under the MIT license. The framework itself is free for any use, commercial or otherwise. Manifest AI has a free tier with community support, and a paid Pro tier for teams who want premium features like project-aware context, team workspaces, and priority support.

    Do I need a build step?

    No. Manifest runs in the browser the moment your <script> tag loads. There's no node_modules, no bundler config, no compile step. The optional prerender CLI (npx mnfst-render) produces a static MPA for SEO and AI crawlers, but it's not required during development.

    Is Manifest production-ready?

    Yes. Manifest is used in production on websites including the official documentation site (manifestx.dev). It ships with first-class SEO and AEO support, multi-locale routing, Appwrite integration for backend services, and a tested prerender pipeline with content-hash caching.

    How does Manifest compare to other frameworks?

    Manifest combines the simplicity of HTMX (HTML-first, no build) with the reactivity of React or Vue (components, data binding) and the static-output benefits of Astro (SEO-baked HTML). Unlike all of those, it requires no build step and no framework runtime ramp-up — see the comparison section above for side-by-side examples.

    Can I use Manifest with Tailwind CSS?

    Yes. Manifest's theme system uses CSS custom properties and works alongside Tailwind utilities. Add the `data-tailwind` attribute to the Manifest script tag and prerendering compiles your Tailwind utilities automatically. Both styling approaches coexist without conflict.

    Does Manifest support TypeScript?

    Manifest itself is plain HTML and JavaScript — no TypeScript required. If you prefer TypeScript for your project's logic, it works fine alongside Manifest. The framework doesn't require you to opt into any specific tooling.

    What is Manifest AI?

    Manifest AI is an integration that connects your AI coding editor (Claude Code, Cursor, Windsurf, or any MCP-compatible tool) directly to Manifest's framework knowledge. Your editor learns Manifest's components, directives, data patterns, and prerender behavior — so it generates correct Manifest code instead of guessing at framework idioms.

    Is Manifest AI a chatbot like ChatGPT or Claude?

    No. Manifest AI doesn't replace your existing AI tools — it enhances them. You keep using Claude, ChatGPT, Cursor, or whichever editor you prefer. Manifest AI is the bridge that gives them deep, accurate understanding of Manifest's framework so the code they generate works on the first try.

    How do I prerender my Manifest site for SEO?

    Run `npx mnfst-render` from your project root. The CLI compiles every route to a static HTML file with auto-generated meta tags, OpenGraph and Twitter card metadata, JSON-LD structured data, OG image snapshots, llms.txt for AI crawlers, and a sitemap. No additional configuration required.

    How does Manifest handle multilingual sites?

    Add locale columns to a CSV file or use per-language YAML/JSON files. Manifest routes locale-prefixed URLs automatically (/fr/about, /zh/about), sets the document's lang and dir attributes, and prerenders one HTML file per locale with proper hreflang alternates.

    Can I deploy Manifest sites to any host?

    Yes. Manifest produces static HTML, CSS, and JavaScript files. Deploy to any static host — Netlify, Vercel, Cloudflare Pages, GitHub Pages, S3, or your own server. No Node.js runtime is required in production.

    Where do I get help?

    Start with the documentation at manifestx.dev/docs. For community support, check GitHub Discussions and our Discord server. Paid Manifest AI subscribers get priority email support and direct access to the team.
