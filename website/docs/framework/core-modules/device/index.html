Devices

Share sheets, secure storage, deep links, push, lifecycle, haptics, biometrics and the camera as Alpine magics that fall back to the web.

Overview

Each magic talks to Capacitor inside a Capacitor app and to a web equivalent, or an honest no-op, in a browser. The same markup runs as a website, an installed PWA and a packaged app.



<span x-text="$device.online ? 'Online' : 'Offline'"></span>
<span x-text="$device.standalone ? 'Installed' : 'In a browser tab'"></span>
<span x-text="$device.os"></span>



    Online
    In a browser tab
    macos

Setup

Device is opt-in. It loads on its own when a page uses one of its magics, when manifest.json has a device block, or inside a Capacitor app. The + prefix keeps the default modules and adds it explicitly. native still works as an alias in both places.




<script src="https://cdn.jsdelivr.net/npm/mnfst@latest/lib/manifest.min.js"
    data-modules="+device"></script>


{
  "device": {}
}

Capacitor plugins are read from window.Capacitor.Plugins. Install the ones you use when packaging the app.

Inside the app, a plugin counts only once npx cap sync has added it to the native project and the app is rebuilt. A web build that bundles Capacitor plugins uses the same web equivalents, never the plugins' web stubs. $secure is the exception: if its plugin is bundled but not added to the native project, it rejects rather than falling back to localStorage.

$device Properties

$device is part of the core utilities and always available. This module only adds Capacitor's network and platform readings to it.

$share

$share() opens the native share sheet inside a Capacitor app (Share) and the Web Share sheet in a browser. Without Web Share it copies the URL, or the text, to the clipboard. It resolves { shared, method, cancelled?, error? }; method is native, web, clipboard or none.



<button @click="$share({ title: 'Manifest', text: 'Supercharged HTML', url: 'https://manifestx.dev' })">Share</button>





    
    Share sheet, or the clipboard where there is none.

$camera

photo() captures and pick() chooses from the library (Camera). Both resolve { dataUrl, format }, or { cancelled: true } with an error when something failed. Inside an app, photo({ quality }) sets the JPEG quality (default 90). On the web both open a file picker; on a phone photo() asks for the camera.



<div x-data="{ shot: null }">
    <button @click="shot = await $camera.photo()">Take a photo</button>
    <img x-show="shot?.dataUrl" :src="shot?.dataUrl" alt="">
</div>





    

        
        
        A file picker in this browser.

$app

$app.active is true in the foreground. Capacitor reports appStateChange (App); the web uses visibilitychange, pageshow and pagehide. $app.onChange(fn) runs on each transition.



<div x-data="{ away: 0 }" x-init="$app.onChange(active => { if (!active) away++ })">
    <span x-text="$app.active ? 'Active' : 'In the background'"></span>
    <span x-text="away + ' times away'"></span>
</div>





    Active
    0 times away
    Switch tabs and come back.

$secure

Key/value storage. Inside a Capacitor app it uses the Keychain or Keystore through @aparajita/capacitor-secure-storage, under that plugin's default capacitor-storage_ prefix. In an app with no such plugin installed, every call rejects rather than falling back to unencrypted storage: install it and run npx cap sync, or provide one with $secure.use(adapter). On the web it is localStorage under an mnfst: prefix, which is not encrypted. get() resolves a string or null. In the app, a failed Keychain or Keystore call rejects with the plugin's error. Values are plain strings, so they read back through the plugin's own getItem()/setItem() but not its JSON-encoding get()/set(), and setKeyPrefix() has no effect on $secure.



<div x-data="{ value: null }">
    <button @click="await $secure.set('token', 'abc123')">Set</button>
    <button @click="value = await $secure.get('token')">Get</button>
    <button @click="await $secure.remove('token'); value = null">Remove</button>
    <code x-text="JSON.stringify(value)"></code>
</div>





    
    
    
    token: null

keys() lists stored keys and clear() removes them all. A different module registered as SecureStorage works if it has getItem/setItem/removeItem or get/set/remove with { key, value }; if the latter rejects for a missing key, so does get(). For anything else, hand over an object with async get, set, remove, keys and clear once with $secure.use(adapter).

$haptics

impact(), notification() and selection() map to Capacitor Haptics. The web falls back to navigator.vibrate, which desktop browsers and iOS Safari ignore.



<button @click="$haptics.impact('LIGHT')">Light</button>
<button @click="$haptics.impact('HEAVY')">Heavy</button>
<button @click="$haptics.notification('SUCCESS')">Success</button>





    
    
    
    No feedback on a desktop browser.

impact takes LIGHT, MEDIUM (default) or HEAVY; notification takes SUCCESS (default), WARNING or ERROR. vibrate(ms) is a plain buzz (default 300ms).

$links

Inside a Capacitor app (App) a tapped universal link like https://app.example.com/order/123, or a custom scheme like myapp://order/123, is routed to /order/123 through the router. $links.open(url) runs the same path by hand; $links.last keeps the latest inbound URL.



<button @click="$links.open('myapp://docs/core-modules/device')">Open a deep link</button>
<code x-text="$links.last"></code>





    
    last: none
    The scheme maps to this page's route.

$links.on(fn) replaces the default routing; fn receives { url, path }.

Universal links and Android App Links need apple-app-site-association and assetlinks.json on your domain. Put them in a .well-known/ folder at the project root; it publishes from SPA and prerendered projects alike.

$push

$push.permission is prompt, granted, denied or unsupported. Nothing is asked until you call $push.request(), which prompts and resolves the new state.



<span x-text="$push.permission"></span>
<button @click="$push.request()">Enable notifications</button>





    permission: denied
    
    Opens the browser's permission prompt.

Inside a Capacitor app (PushNotifications), register() registers with APNs or FCM, onToken(fn) receives the device token for your backend, onReceive(fn) fires in the foreground, and a tapped notification routes to its url or route unless onTap(fn) takes over. On the web, permission maps to the Notification API; register() is a no-op and token stays null.

$biometric

available() resolves true when @aparajita/capacitor-biometric-auth or @capgo/capacitor-native-biometric reports Face ID, Touch ID or Android biometrics. verify(opts) resolves { verified: true }, or { verified: false, error, code } with the plugin's own error code: strings such as userCancel from aparajita, numeric strings from capgo. The web has no equivalent: available() is false and verify() reports unsupported.



<div x-data="{ can: null, confirmed: false }" x-init="can = await $biometric.available()">
    <button x-show="can" @click="confirmed = (await $biometric.verify({ reason: 'Confirm payment' })).verified">Pay with Face ID</button>
    <span x-show="confirmed">Payment confirmed.</span>
    <span x-show="can === false">Biometrics are not available here.</span>
</div>





    available: false
    
    Not available in a browser.
Option Description
reason Why you are asking; shown in the prompt
title, subtitle Prompt heading (Android)
cancelTitle Cancel button label
fallbackTitle Passcode fallback button label (iOS)
allowDeviceCredential Let the device passcode stand in for biometrics (no effect on Android with capgo)
