Data-* Attributes

Module Loading

The manifest.js script tag accepts data-* attributes to control module loading:

Attribute Default Description
data-modules (auto) Comma-separated list of modules to load; prefix a name with + to add it to the defaults instead of replacing them. A list with any name not prefixed with + loads exactly the listed modules, and on-use loading is off
data-omit — Comma-separated, case-insensitive list to exclude from the loaded set, with or without data-modules. An omitted module is never loaded by the loader, even when the page uses it, and the console shows one warning naming it. A module another loaded module depends on still loads
data-version latest, or the loader's own version when its tag has integrity Module version to fetch from CDN
data-alpine The version tested with this framework release Alpine version, a full URL, or a path starting with /
data-alpine-integrity — Hash for a data-alpine version or URL, required when integrity checks are on — see security
data-integrity (on when the tag has integrity) Boolean — check everything the loader and modules load against published hashes; warn logs instead of refusing; off or false turns the checks off
data-tailwind (off) Boolean — load Manifest's Tailwind v4 build. cache also keeps its output in the browser for repeat visits (opt-in) — see theme
data-module-base CDN Base URL/path for module scripts (for self-hosted deployments)
data-defer (on) off turns off automatic deferral of closed containers — see performance
data-defer-routes (off) Boolean — experimental; defer inactive x-route pages until first shown
data-sw (auto) off never registers the app-shell service worker — see web apps

On-Use Modules

Without a fixed data-modules list, these modules load when the page uses them: markdown, code, svg, combobox, slides, colorpicker, datepicker, charts, virtual, export (which also provides import; import works as a name), rich-text, submissions, chat, appwrite-presences and device. Chat, appwrite-presences and device also load when manifest.json configures them. The loader looks for their attributes (x-markdown, x-chart, x-date and so on, with or without modifiers), for <pre><code class="language-…"> and <code copy>, and for their magics ($chart, $chat, $export, …) in attributes and inline scripts. Components, x-html and other content added later are checked as they arrive.

Content waiting for a module. An element whose directive needs a module still on its way (markdown, code, svg, combobox, slides, colorpicker, datepicker, charts, virtual or export) is held until the module is ready, then starts as usual. While held, it shows but doesn't respond: clicks on it are lost, while text typed into its fields is kept and handed to x-model when it starts. Its own x-data state isn't available yet. Markdown, code and SVG stay invisible while held, so raw source never shows. If a module fails to load, or loads but hasn't started 10 seconds later, held elements start without it and the console says so.

What the loader can't see. Add the module with data-modules="+name" when it is used only in ways the page's markup doesn't show:

  • directives applied through Alpine.bind or an x-bind object
  • a magic used only in a separate script file. $chart, $colorpicker, $date, $export and $import still load on first use, after a short delay; the others ($chat, $presence, $rich and the device magics) need +name unless manifest.json already loads them
  • $import called before its module has loaded: the browser may refuse to open the file picker because the click has expired by the time the module arrives, and the console warns. Use data-modules="+import"

With an Alpine version set through data-alpine that lacks Alpine.deferInit, elements are not held: they start at once, and the module's directive is applied when it arrives.

Routing & View Transitions

Attributes for managing crossfades between routes:

Attribute On Description
data-no-prefetch <a> element Opt this link out of hover-based component prefetching
data-view-transitions <html> Force-on SPA view transitions, regardless of page size
data-no-view-transitions <html> Force-off SPA view transitions
data-no-view-transition any element Exclude this element from SPA/MPA view transition snapshots (sets view-transition-name: none)

Rendering

The npx mnfst-render command compiles MPA websites optimized for SEO/AEO, and scans for these attributes:

Attribute On Description
data-hydrate any element Preserve dynamic functionality so Alpine can re-initialize the subtree at runtime
data-static any element Bakes the subtree to its rendered output, which Alpine ignores at runtime

Directives

Directives are custom HTML attributes from Alpine that provide reactive functionality. Manifest extends these to cover a wide variety of application use cases.

Alpine Directives

See alpinejs.dev for details.

Route Patterns

Values for x-route are:

Pattern Matches
=path Exact match only
path Prefix match (also matches sub-paths)
path/* Wildcard (catches /path/anything)
path1, path2 Multi (any of the listed)
!path Negation (matches anything except path)
!* Catch-all (404) — matches when no other route did

Data Source Operators

Each $x.<source> returns an object or array. Standard JS array methods apply when the source is an array. Manifest also exposes:

State

Property Type Description
$loading boolean True during fetch / mutation
$error Error | string | null Last error, or null
$ready boolean True after initial load completes
$stale boolean True while cached rows show and fresh data is still loading
$fresh Promise Resolves once fresh data has landed

Filtering

Method Description
$search(term, ...fields) Substring match across the listed fields
$search(term, { field: weight }) Ranked search — every term must match; higher-weight fields rank first
$query([...exprs]) Filter using query expressions. Local sources: synchronous filter. Appwrite sources: server-side, returns Promise
$route(field) The row whose field value matches a segment of the current URL (e.g. $x.articles.$route('slug')). Not the same as the $route magic, which is the current route string

Mutations

Available on cloud data sources (Appwrite tables) and bucket sources where applicable.

Method Description
$create(data, rowId?) Create a new entry. For buckets: $create(file, fileId?, permissions?, onProgress?) uploads a file. Returns the created entry / file
$update(idOrArray, data) Update one or many entries by id. Returns the updated entry / entries
$delete(idOrArray) Delete one or many entries by id. Returns the deleted entry / entries
$duplicate(id, options?) Copy an entry / file. Table options: newRowId, files ('duplicate' | 'same' | 'none'), plus field overrides. Bucket options: newName, newFileId

Pagination

Available on cloud data sources.

Method Description
$first(limit) Cursor-based first page. Returns { items, cursor, total, hasMore }
$next(cursor, limit) Cursor-based next page. Same shape as $first
$prev(cursor, limit) Cursor-based previous page. Same shape; hasMore is always true
$page(pageNumber, limit) Offset-based specific page. Returns { items, page, total, totalPages, hasMore }

Files

Available on bucket (storage) sources.

Method Description
$url(fileId, token?) View URL for a file
$download(fileId, token?) Download URL for a file
$preview(fileId, options?, token?) Preview URL with image transforms (images only)
$openUrl(fileId, token?) Open the view URL in a new tab
$openDownload(fileId, filename?, token?) Open the download URL in a new tab
$openPreview(fileId, options?, token?) Open the preview URL in a new tab

$preview options include width, height, quality, output, gravity, borderWidth, borderColor, borderRadius, opacity, rotation, and background.

Row Properties

Manifest-added properties exposed on every row returned by $x.<source>. Coexist with the source's own column values.

Property Type On Description
$id string any Unique identifier (Appwrite system field)
$createdAt string any Creation timestamp, ISO format
$updatedAt string any Last update timestamp, ISO format
$files array table rows Files linked to the entry when storage is configured
$formattedSize string file rows Human-readable file size (e.g. "2.5 MB")
$url string file rows View URL for the file
$isImage boolean file rows true if the file is an image
$thumbnailUrl string file rows Thumbnail URL (images only)

Queries

$query accepts an array of [method, attribute, value] query expressions. The same syntax works for local and cloud sources (except search) — local runs synchronously in the browser, cloud runs server-side and returns a Promise.

Method Form Notes
equal ['equal', 'attr', value] Exact match
notEqual ['notEqual', 'attr', value] Inverse of equal
greaterThan ['greaterThan', 'attr', value] >
greaterThanOrEqual ['greaterThanOrEqual', 'attr', value] ≥ (greaterThanEqual also works)
lessThan ['lessThan', 'attr', value] <
lessThanOrEqual ['lessThanOrEqual', 'attr', value] ≤ (lessThanEqual also works)
between ['between', 'attr', min, max] Inclusive range
isNull ['isNull', 'attr'] Null check
isNotNull ['isNotNull', 'attr'] Non-null check
contains ['contains', 'attr', 'value'] Substring match (case-insensitive)
startsWith ['startsWith', 'attr', 'value'] Prefix match
endsWith ['endsWith', 'attr', 'value'] Suffix match
search ['search', 'attr', 'value'] Full-text search — cloud sources only, and they need a fulltext index. Locally it doesn't filter; use $search
orderAsc ['orderAsc', 'attr'] Sort ascending
orderDesc ['orderDesc', 'attr'] Sort descending
orderRandom ['orderRandom'] Random order
limit ['limit', n] Cap result count
offset ['offset', n] Skip results

State Management

Manifest projects have three options to manage state, distinguished by lifetime and audience.

Layer Tool Use for
Component-local x-data UI toggles, form inputs, ephemeral interaction state
Cross-component (global) Alpine.store(name, ...) Shopping cart, state shared across views
Server / persistent $x.<source> Anything backed by a file, HTTP endpoint, or cloud database collection

Component-Local

Inline state per component. Resets when the element is destroyed. Most common.

<div x-data="{ open: false }">
    <button @click="open = !open">Toggle</button>
    <p x-show="open">Hello</p>
</div>

For non-trivial logic, extract to an Alpine.data() factory (still local, but easier to test):

<script>
document.addEventListener('alpine:init', () => {
    Alpine.data('cart', () => ({
        items: [],
        add(p) { this.items.push(p); },
        get total() { return this.items.reduce((s, i) => s + i.price, 0); }
    }));
});
</script>

<div x-data="cart()">
    <button @click="add({ id: 1, price: 10 })">Add</button>
    <span x-text="total"></span>
</div>

Global (Alpine Stores)

Shared across all components. Define once, read anywhere via $store.name.

<script>
document.addEventListener('alpine:init', () => {
    Alpine.store('cart', {
        items: [],
        add(p) { this.items.push(p); },
        get total() { return this.items.reduce((s, i) => s + i.price, 0); }
    });
});
</script>

<button @click="$store.cart.add({ id: 1, price: 10 })">Add</button>
<span x-text="$store.cart.total"></span>

Stores live for the page's lifetime. They reset on full reload — no built-in persistence; pair with localStorage or Alpine's persist plugin if you need it.

Server / Persistent

Use $x.<source> for anything that lives in a file or backend. The data layer handles loading state, querying, and (for Appwrite) mutations.

<div x-data>
    <template x-for="p in $x.products.$query([['greaterThan', 'stock', 0]])">
        <div x-text="p.name"></div>
    </template>
</div>

Derived State

Three options, in increasing decoupling:

Pattern When
Inline expression <span x-text="count * 2"> — re-evaluates automatically. Best for trivial cases.
Computed getter get doubled() { return this.count * 2 } on x-data or store. Best for component- or store-level computeds.
$watch('prop', cb) Side-effects on change (e.g. write to localStorage, call API).
x-computed:name / $computed(s => ...) Data-sized work (filtered or sorted lists, totals) recalculated only when its inputs change. See computed values. 
<div x-data="{ count: 0 }"
     x-init="$watch('count', v => localStorage.setItem('count', v))">
    <button @click="count++" x-text="count"></button>
    <span x-text="count * 2"></span>
</div>

Avoid x-effect unless you need imperative side-effects with reactive deps that can't be expressed inline.

Cross-Component Communication

Pattern Description
Shared x-data on a common parent Children read/write parent state directly. Tight coupling.
Alpine.store('name', ...) All components access the same store. Loose coupling.
$dispatch('event-name', detail) + @event-name.window Pub/sub across the DOM. Loosest coupling.

CSS Variables

Variable family Purpose
--color-* Theme colors (background, content, brand, accent variants — light/dark)
--font-* Font families
--radius Default border radius
--shadow-* Box shadows
--spacing Base spacing unit
--spacing-* Content width, viewport padding, field sizes, popover offset

Manifest Events

Custom events dispatched on window that any component can subscribe to via @event-name.window.

Event When fired event.detail
manifest:route-change After SPA route change (and inside the view transition when active) { from, to, normalizedPath }
manifest:components-processed After components and templates have been registered —
manifest:render-ready Signal from the data module that prerender can snapshot the page —
manifest:dev-reload Dev server (mnfst-run): a data or markdown file (.csv, .json, .yaml, .md) changed —
submit:sent, submit:error On an x-submit form (not window; bubbles), when the endpoint answers or the request fails { ok, status, data, response, error, message }
manifest:defer-render On a deferred container (not window), after its contents initialise —
manifest:virtual-recycle On a reused row's root in an x-virtual list with recycle: true (not window; doesn't bubble), after the row takes its new item { key, index }
alpine:init Alpine initialization (standard Alpine event) —

Listen example:

<div x-data @manifest:route-change.window="console.log('route:', $event.detail.to)"></div>
